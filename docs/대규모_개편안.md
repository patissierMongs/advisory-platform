# 대규모 개편안 — 추출 엔진·운영 보정·조치율 측정 개편

> 대상 리비전: 이 문서와 같은 브랜치의 구현. "틀은 잡혔으나 실무 사용이 어렵다"는 운영 피드백을
> 받아, **추출 정확도 · 잘못된 데이터의 현장 보정 · 개별 대상 단위 조치율 측정 · 화면 가독성**
> 네 축을 일괄 개편했다. 모든 항목은 구현 완료 상태이며 자동 테스트로 고정되어 있다.

---

## 1. 추출 엔진 개편

### 1-1. 문제
| # | 기존 동작 | 실무 문제 |
|---|---|---|
| 1 | 제품 정규화가 "부분 문자열 포함" 매칭 | **Apache Storm → `apache`(httpd)로 오인.** 사전에 없는 Apache 하위 제품 전부가 HTTPD 자산과 매칭됨 |
| 2 | PDF에서 CVE 코드만 추출 | 본문에 명시된 영향 제품·버전 정보를 버리고 CVE DB에만 의존 → 폐쇄망에서 피드가 없으면 영원히 진행 불가 |
| 3 | 버전 해석 없음(자산대장 열거 비교뿐) | "X **이하**" 문구가 열거 1건으로 좁혀져 하위 버전 자산 누락 |
| 4 | — | "X **이상으로 업데이트**"의 X(조치 권고 버전)가 영향 버전으로 오인될 구조 |
| 5 | CVE 1건 = 제품 1개 | HTTP 취약점처럼 Apache·Tomcat·IIS·nginx 여러 제품이 걸리는 CVE 표현 불가 |
| 6 | 숫자 정규식 | 날짜·문서번호·CVE 일련번호·퍼센트가 전부 버전 후보가 될 위험 |

### 1-2. 개편 내용
**(a) 제품 정규화 재작성 — `app/core/normalize.py`**
- 별칭 매칭을 **토큰 경계 + 최장일치**로 교체. `iis`가 "aiis" 내부에 걸리지 않는다.
- **벤더 접두어 가드**: `apache`·`microsoft` 등 벤더명 단독 별칭은 뒤에 다른 제품 단어가
  이어지면 매칭을 거부한다. `Apache Storm` → `apache_storm`, 사전에 없는 `Apache Druid` →
  슬러그 `apache_druid`. **HTTPD와 절대 섞이지 않는다.**
- 별칭 사전 확장: tomcat/storm/kafka/struts/log4j/iis/nginx/esxi/mysql/postgres 등.

**(b) 제품·버전 추출기 신설 — `app/core/product_extract.py`**
- 본문에서 **제품 언급의 문맥 창(160자) 안에서만** 버전을 인식 → 문서 내 임의 숫자가
  버전으로 빨려 들어가지 않음(날짜·`제…호`·CVE 일련번호·`%` 문맥 배제 필터).
- 한국어 범위 구문 해석: `X 이하`→`{lte}`, `X 미만`→`{lt}`, `X 이상`→`{gte}`, `X 초과`→`{gt}`,
  `A ~ B`→`{range}`, `및 이전 버전`, 영문 `prior to/and earlier` 지원.
  **보안권고문 특성상 "이하"는 하위 버전 전체 범위로 저장**된다(열거 아님).
- **조치(fix) 버전 분리**: `X (이상)으로 업데이트/업그레이드/패치` 류는 영향 버전이 아니라
  `fixed_version`으로 저장하고, 명시적 영향 범위가 없으면 `{lt: X}`를 유도한다
  (fix 미만 전체 취약 — 실무 관례와 일치).
- **다중 제품**: 한 권고문에서 Apache·Tomcat·IIS·nginx 각각의 규칙을 독립 추출.
- **미등록 제품 제안**: `"<제품명> <버전> 이하"` 명시 범위 구문이면 사전에 없는 제품도
  저신뢰(0.5) 제안으로 올린다 — "추출 제품 추가 제안" 요구 대응.

**(c) 데이터 모델 — `advisory_product` 테이블 신설**
- `status`: `SUGGESTED`(추출 제안) / `CONFIRMED`(관리자 확인) / `DELETED`(소프트 삭제),
  `origin`: `EXTRACTED` / `MANUAL`. 규칙 형식은 CVE와 동일(`열거 | {lt,lte,gt,gte,eq} | {range} | "*"`).

**(d) 버전 비교기 확장 — `app/core/versioning.py`**
- `{gte: A, lte: B}` 같은 **복수 연산자 dict를 AND로 평가**(기존은 첫 연산자만 보고 종료).

### 1-3. 현장 보정 API (STEP2 화면에 전부 노출)
| 작업 | API |
|---|---|
| 제품 목록/추가/수정/삭제/복원 | `GET·POST /advisories/{id}/products`, `PATCH·DELETE /advisory-products/{id}`, `POST …/restore` |
| **수동 재추출**(삭제한 추출 제안도 복귀) | `POST /advisories/{id}/products/reextract` |
| **CVE 적용** — 추출 규칙으로 로컬 CVE 레코드 생성/보강 → DB 미등록 게이트 해소 | `POST /advisory-products/{id}/apply-to-cve` |

`CVE 적용`은 폐쇄망 운영의 핵심 보완이다: 피드 반입 없이도 권고문 본문의 제품·버전으로
로컬 CVE를 등록해 매칭 단계로 진행할 수 있다. 기존 CVE에 다른 제품이 이미 있으면
`affected_products`(다중 제품)로 병합한다.

## 2. 추출 CVE 보정 — 수정·소프트 삭제·복원

- **그 자리 수정**: `PATCH /advisory-cves/{id}` — 오추출 코드를 삭제/재등록 없이 교정.
  기존 매칭 정리·DB 재조회·게이트 재평가까지 원자적으로 수행. STEP2 칩의 ✎ 버튼.
- **소프트 삭제**: 삭제해도 행이 `is_deleted`로 남아 **복원 가능**(`POST …/restore`),
  화면의 "삭제됨(복원 가능)" 칩. **재추출해도 삭제 의사가 보존**된다(되살아나지 않음).
- 동일 코드를 다시 수동 추가하면 삭제분이 복원으로 처리된다.
- 게이트·심각도·보고서·게시판·PDF 하이라이트 등 모든 집계는 삭제분 제외 기준으로 통일.

## 3. CVE 다중 제품 지원

- `cve.affected_products`(JSON) 신설 — primary 외 (제품키, 규칙) 목록.
- 매칭 엔진이 **CVE의 모든 제품 규칙**을 자산 제품키와 대조(`cve_product_rules`).
- NVD 피드 파서가 CPE의 **모든 제품**을 적재(기존: 첫 CPE 근사 1건). CPE 버전 경계도
  `Start/End × Including/Excluding` 전 조합 해석으로 확장.

## 4. 출처기관 일괄 지정 — "빈 출처만"

- 업로드 시 출처기관을 **선택 입력**으로 완화(비우면 "출처 미지정"으로 접수).
- 권고문 목록에 **일괄 지정 바** 신설: 카드 체크박스 + **"빈 출처만 선택"** 버튼(출처가
  비어 있는 권고문만 자동 선택·필터) + 출처 입력 + 일괄 적용.
- `POST /advisories/source-org` — `only_empty=true`(기본)면 서버에서도 빈 출처만 갱신해
  기존 값을 이중으로 보호. 출처 있는 건이 섞이면 화면이 덮어쓸지 확인을 받는다.
- 개별 수정도 `PATCH /advisories/{id}/meta`의 `source_org`로 가능.

## 5. 자산 엑셀 다중 시트

- 미리보기 응답에 **전체 시트 목록**(`sheets`) 포함, 화면에 **시트 선택 드롭다운** 추가.
- 커밋 시 선택 시트 반영, **"전체 시트" 체크** 시 같은 매핑으로 모든 시트 일괄 적재
  (부서별 시트로 쪼개진 자산대장). 시트별 헤더행 자동 감지, 경고에 시트명 표기,
  자동 자산번호의 시트 간 충돌 방지, replace 회수 판정은 전 시트 적재 후 1회.

## 6. 발송이력 — 개별 대상(자산) 단위 측정 + 회신 취소

- `GET /history/advisories`가 부서 묶음 외에 **자산 단위 ack 집계**를 제공:
  부서별 `asset_ack {total, done, in_progress, unable, none, done_rate}` +
  권고문 전체 `asset_total/asset_done/asset_done_rate`.
- 화면: 헤더에 **부서 완료율/자산(개별) 조치율** 병기, 부서 행에 `자산 M/N대 (r%)` + 미니바.
- **조치 회신 취소**: 같은 상태 버튼 재클릭 → **"정말 취소하시겠습니까?" 확인 팝업** →
  `NONE` 회신으로 부서·소속 자산 상태가 일괄 원복. 조치관리 콘솔(드롭다운 NONE)과
  게시판(댓글 "회신 취소" 옵션)에도 동일한 확인 팝업 적용.
- 게시판 자산 회신 취소로 "부서 전체 완료"가 깨지면 발송이력 부서 종결(ACKED)도
  자동 해제 — 자산 기준/부서 기준 화면 간 불일치 차단.

## 7. 권고문 처리 페이지 시각 개선

- 카드에 **처리 단계 미니 트래커**(접수→추출→매칭→발송→완료), **최고 심각도 칩**,
  **D-day/기한초과 배지**, 발송 후 **자산 조치 진행 미니바**(자산 M/N · 부서 회신 m/n).
- 목록 **검색**(제목·문서번호·출처) + **상태 필터 칩**(처리중/CVE 미등록/발송·완료/실패/출처 미지정).
- 출처 미지정 카드는 주황 "출처 미지정" 배지로 즉시 식별.
- STEP2에 **본문 추출 영향 제품·버전 패널**(확인/수정/CVE 적용/삭제/복원/수동 재추출)과
  CVE 칩 수정(✎)·복원 UI, 재추출 버튼 추가.

## 8. 호환성·마이그레이션

- SQLite 경량 마이그레이션(`app/db.py _ADDED_COLUMNS`)에 `advisory_cve.is_deleted`,
  `cve.affected_products` 추가. `advisory_product` 테이블은 `create_all`로 생성.
- 기존 API 응답은 **필드 추가만** 있고 제거·의미 변경 없음. 단 하나의 의도적 변경:
  업로드 시 출처기관 필수 → 선택 (§4).

## 10. 남은 제안(후속)

- 제품 별칭 사전의 DB 이관 + 관리자 편집 화면(현재 모듈 상수 + 런타임 등록 API 수준).
- OCR(스캔본 PDF) 파이프라인 — 현재는 실패 안내 + 수동 보정 흐름.
- 추출 신뢰도 기반 자동 확인(고신뢰 규칙 자동 CONFIRMED) 옵션.
- 발송이력 자산 단위 표의 자산별 드릴다운(현재는 게시판 상세에서 자산별 확인).

## 11. 후속 개편(2차) — 피드 연동·관리 인덱스·UI 재배치

1. **피드 → 추출 사전 자동 동기화**: CVE 피드 적용 시 CVE DB의 제품명이
   본문 추출 별칭 사전에 자동 등재(`normalize.sync_aliases_from_cves`).
   서버 기동 시에도 1회 동기화 — 피드만 갱신하면 추출 리스트가 따라온다.
2. **권고문 목록 제품 표시·검색**: 파일명(제목) 우측에 제품 칩 나열(클릭 시 그
   제품으로 필터), 검색이 제목·문서번호·출처 외에 **제품명·키·버전·CVE**까지 커버.
3. **피드 실패 이력 정직화**: 적용 중 예외 → `FAILED` + `error_message` 기록,
   갱신 이력에 빨간 "실패 · 반영 안 됨" 필로 표시(성공 위장 제거).
4. **STEP2 배치**: PDF 이전/다음 페이저를 문서 위로 이동.
5. **제품 패널 재배치 + 인라인 편집**: 본문 추출 영향 제품·버전 패널을 CVE 조회
   결과 위로. `prompt()` 팝업 전면 제거 — 추가/수정/CVE 코드 교정 모두
   그 자리 텍스트박스(+ CVE 적용 select).
6. **관리 인덱스 테이블 신설**(`advisory_index`): 문서번호·CVE 목록·대상 제품
   (여러 개)·버전(여러 개)·날짜·배포기관을 권고문별 1행으로 집약(JSON) +
   `search_text` 평탄화. 모든 변이 지점에서 멱등 재색인, 목록 조회 시 지연 백필.
   **CVE가 없는 권고문도 문서번호·제품으로 검색·관리 가능.**
7. **미완료 권고문 자동 재작업**: 피드 적용마다 종결(완료·보관) 제외 전 권고문을
   재추출(관리자 확인/수동/삭제 이력 보존)·재매칭(MATCHED·NOTIFYING)·재색인 —
   게시판/목록이 다음 조회부터 즉시 반영.

검증: `tests/test_ops_followup.py` 4건 포함 전체 스위트 106건 통과.
Chromium 실기동으로 페이저 위치·패널 순서·인라인 편집·제품 칩 검색·실패 필 확인.
